# Supervaizer CLI

> **Created:** 2025-08-06
> **Updated:** 2026-09-25

```bash
pip install supervaizer               # core
pip install "supervaizer[deploy]"     # adds the deploy commands (quote the brackets in zsh)

supervaizer --help
supervaizer --version                 # -v; the CLI also checks PyPI and prints a notice when a newer release exists
```

## scaffold

Creates `supervaizer_control.py` (the controller definition) and `supervaize_instructions.html` (agent setup instructions) in the current directory.

```bash
supervaizer scaffold                          # both files
supervaizer scaffold --output-path my_ctl.py  # custom control file path (env: SUPERVAIZER_OUTPUT_PATH)
supervaizer scaffold --force                  # overwrite existing files (env: SUPERVAIZER_FORCE_INSTALL=true)
supervaizer scaffold instructions             # only the instructions page (--control-file, --output-path, --force)
supervaizer scaffold refresh-instructions     # regenerate the instructions page from the control file
```

## start

```bash
supervaizer start [SCRIPT_PATH] [OPTIONS]
```

Loads the control script (default `supervaizer_control.py`, env `SUPERVAIZER_SCRIPT_PATH`), finds the first `Server` instance in it, applies the host, port, and public URL from the command line, and launches it.

| Option | Env var | Default | Notes |
| --- | --- | --- | --- |
| `--public-url` | `SUPERVAIZER_PUBLIC_URL` | `scheme://host:port` | URL Studio uses to reach the controller |
| `--host` | `SUPERVAIZER_HOST` | `0.0.0.0` | Ignored in local mode (binds `127.0.0.1`) |
| `--port` | `SUPERVAIZER_PORT` | `8000` | |
| `--environment` | `SUPERVAIZER_ENVIRONMENT` | `dev` | |
| `--log-level` | `SUPERVAIZER_LOG_LEVEL` | `INFO` | `SUPERVAIZER_LOG_FORMAT=json` switches to structured logs |
| `--persist` / `--no-persist` | `SUPERVAIZER_PERSISTENCE` | off | File persistence under `DATA_STORAGE_PATH`; see [2025_08_PERSISTENCE.md](2025_08_PERSISTENCE.md) |
| `--local` | none | off | Local test mode, see below |
| `--debug`, `--reload` | `SUPERVAIZER_DEBUG`, `SUPERVAIZER_RELOAD` | off | Only set the env vars; `Server` does not read them, so they have no effect with a control script |

### Studio-registered controllers

When the control script sets `supervisor_account` and A2A endpoints are enabled (the default), launch fails unless workspace authorization is configured:

```text
Studio-registered Supervaizer v2 A2A requires workspace authorization.
Set SUPERVAIZER_WORKSPACE_AUTH_REQUIRED=true and configure
SUPERVAIZER_WORKSPACE_AUTH_ISSUER plus either
SUPERVAIZER_WORKSPACE_AUTH_PUBLIC_KEY or SUPERVAIZER_WORKSPACE_AUTH_JWKS_URL.
```

See [2026_05_WORKSPACE_AGENT_GRANTS.md](2026_05_WORKSPACE_AGENT_GRANTS.md) for the model.

### Local mode (`--local`)

```bash
supervaizer start --local
```

- Sets `SUPERVAIZER_LOCAL_MODE=true`; the workspace authorization check above is skipped.
- Skips Studio registration (`supervisor_account` is ignored).
- Binds `127.0.0.1` even if `--host` is given, and overwrites `SUPERVAIZER_PUBLIC_URL` unless `--public-url` is passed explicitly.
- Loads `./.env` without overriding variables already set.
- API key defaults to `local-dev` (override with `SUPERVAIZER_API_KEY`).
- Adds the built-in Hello World agent next to your agents; set `SUPERVAIZER_DISABLE_HELLO_WORLD=true` to skip it. With no control script, only Hello World runs.
- `/manage` (admin UI and workbench) accepts loopback connections; outside local mode it is Tailscale-only.
- v2 actions over `/a2a` still require Studio workspace authorization, so they answer `workspace_authorization_not_configured` in local mode. Use the workbench to run jobs.

## deploy

Requires the `deploy` extra and a `pyproject.toml` in the current directory or up to three parent directories. `--name` is required on every command except `clean`; when omitted the CLI prompts for it, even with `--yes`.

> **Experimental.** `deploy up` builds the image locally but does not push it to a registry, injects generated secrets under names the server does not read, and does not pass the `SUPERVAIZER_WORKSPACE_AUTH_*` variables into the container. `--verbose`, `--yes`, and `--no-rollback` are accepted but do nothing, `--generate-rsa` writes an unread `SV_RSA_PRIVATE_KEY`, and `--port` values other than `8000` break the container. Use `plan` and `local` today, and finish cloud deployment with the provider CLI.

Platforms: `cloud-run` (requires `--project-id`), `aws-app-runner`, `do-app-platform`. `--region` defaults to `us-central1`, `us-east-1`, and `nyc3` respectively. `--env` is `dev` (default), `staging`, or `prod`.

```bash
# Preview (no args prints help)
supervaizer deploy plan --platform cloud-run --name my-agent --project-id my-gcp-project

# Docker smoke test on this machine (see 2025_10_LOCAL_TESTING.md)
supervaizer deploy local --name my-agent [--env dev] [--port 8000] [--generate-api-key] [--timeout 300] [--docker-files-only] [--controller-file PATH]

# Build and provision
supervaizer deploy up --platform cloud-run --name my-agent --project-id my-gcp-project [--region us-central1] [--env dev] [--image registry/repo:tag] [--generate-api-key] [--timeout 300]

# Inspect and tear down
supervaizer deploy status --platform cloud-run --name my-agent [--env dev] [--region ...]
supervaizer deploy down   --platform cloud-run --name my-agent [--env dev] [--region ...]   # also deletes .deployment/

# Remove local artifacts and state
supervaizer deploy clean [--force] [--docker-only] [--state-only] [--verbose]
```

`--image` defaults to `{name}-{env}:{git-sha8}` (or `:latest` outside a git repo). Design record: [RFC-001](rfc/2025_10_001-cloud-deployment-cli.md).

## Environment Variables

### Server

| Variable | Description | Default |
| --- | --- | --- |
| `SUPERVAIZER_PUBLIC_URL` | URL used for inbound connections | `scheme://host:port` |
| `SUPERVAIZER_HOST` | Bind host | `0.0.0.0` (`127.0.0.1` in local mode) |
| `SUPERVAIZER_PORT` | Bind port | `8000` |
| `SUPERVAIZER_ENVIRONMENT` | Environment name | `dev` |
| `SUPERVAIZER_LOG_LEVEL` | Log level | `INFO` |
| `SUPERVAIZER_LOG_FORMAT` | `json` for structured logs | text |
| `SUPERVAIZER_API_KEY` | Controller API key (`X-API-Key`, write scope) | generated at startup, fingerprint logged; `local-dev` in local mode |
| `SUPERVAIZER_PRIVATE_KEY` | RSA private key (PEM) | generated per process |
| `SUPERVAIZER_SERVER_ID` | Stable server identity (UUID) | generated per process |
| `SUPERVAIZER_SCRIPT_PATH` | Control script path | `supervaizer_control.py` |
| `SUPERVAIZER_OUTPUT_PATH`, `SUPERVAIZER_FORCE_INSTALL` | `scaffold` output path and overwrite flag | `supervaizer_control.py`, `false` |
| `SUPERVAIZER_LOCAL_MODE` | Server-side local behaviour (no Studio, Hello World, `local-dev` key); the CLI flag also handles binding, `.env`, and the script fallback | `false` |
| `SUPERVAIZER_DISABLE_HELLO_WORLD` | Skip the built-in agent in local mode | `false` |
| `SUPERVAIZER_PERSISTENCE`, `DATA_STORAGE_PATH` | File persistence toggle and directory | `false`, `./data` |
| `TRUSTED_PROXIES` | CIDRs whose `X-Forwarded-For` is trusted for `/manage` | unset |
| `SUPERVAIZE_HTTP_MAX_RETRIES` | Retries for agent-to-Studio calls | `2` |
| `SUPERVAIZER_DEBUG`, `SUPERVAIZER_RELOAD` | Set by `--debug` / `--reload`; not read by `Server` | `false` |

**Serverless (e.g. Vercel):** each instance may be a new process. Set `SUPERVAIZER_PRIVATE_KEY` and `SUPERVAIZER_SERVER_ID` in the platform environment so every cold start keeps the same key and identity; Studio workspace grants are keyed on the server id.

### Workspace authorization

| Variable | Description | Default |
| --- | --- | --- |
| `SUPERVAIZER_WORKSPACE_AUTH_REQUIRED` | Enable verification of Studio-signed workspace tokens | `false` |
| `SUPERVAIZER_WORKSPACE_AUTH_ISSUER` | Expected token issuer (Studio URL) | unset |
| `SUPERVAIZER_WORKSPACE_AUTH_PUBLIC_KEY` | Ed25519 public key (PEM) | unset |
| `SUPERVAIZER_WORKSPACE_AUTH_JWKS_URL` | JWKS endpoint, alternative to the PEM | unset |
| `SUPERVAIZER_WORKSPACE_AUTH_AUDIENCE` | Optional expected audience override | derived |
| `SUPERVAIZER_WORKSPACE_AUTH_LEEWAY_SECONDS` | Clock skew tolerance | `30` |

### Studio credentials

Read by the scaffolded control script (not by `Server` itself) to build the `Account` passed as `supervisor_account`:

| Variable | Description |
| --- | --- |
| `SUPERVAIZE_API_KEY` | Agent-to-Studio API key |
| `SUPERVAIZE_WORKSPACE_ID` | Studio workspace identifier |
| `SUPERVAIZE_API_URL` | Studio base URL, e.g. `https://app.supervaize.com` |
